### Breaking

- Replace `trace-dispatcher` with `hermod-tracing`, its successor. The
  `ouroboros-network` and `ouroboros-consensus` boundaries remain on
  `contra-tracer`, so configured hermod traces are adapted with `mkTracer`.
  The exported `dmqStartupTracer` field is the one hermod `Trace`, allowing it
  to be passed directly to `hermod-tracing-prometheus`.

### Non-Breaking

- The configuration file is read as before. Like `trace-dispatcher` 2.13,
  `hermod-tracing-core` 1.0.1, which `dmq-node` now requires, accepts both the
  old tracing keys (top-level `TraceOptions`, `TraceOptionMetricsPrefix`, ...)
  and the current ones (`Options`, `MetricsPrefix`, ...), with the same
  meaning. The old names are now deprecated, but nothing warns at run time.
  The shipped configuration and `README.md` use the current names. Only two
  keys matter to `dmq-node`: `TraceOptions` -> `Options` and
  `TraceOptionMetricsPrefix` -> `MetricsPrefix`. It runs no forwarder or
  periodic tracers, and does not read `ApplicationName` or
  `PrometheusSimpleRun`. Rename both keys together. When a top-level
  `TraceOptions` is present, the old layout is read and `Options`,
  `MetricsPrefix` and every other current key in the file are ignored. In a
  file without it, the old keys are ignored. Neither case gives a warning, so
  a custom metrics prefix whose key was not renamed along with the rest is
  silently lost. A migrated file also works with `dmq-node` 0.7.
- The environment variable that overrides the host name in trace messages is
  renamed from `TRACE_DISPATCHER_LOGGING_HOSTNAME` to
  `HERMOD_TRACING_LOGGING_HOSTNAME`. The old name is still read when the new one
  is not set, but it is deprecated and nothing reports its use. Set the new
  one now. Keep the old one as well while you may still roll back to
  `dmq-node` 0.7, which reads only the old name.
